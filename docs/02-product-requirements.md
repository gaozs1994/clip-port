# 视频解析工具产品需求文档（PRD）

> 版本：0.1  
> 日期：2026-09-16  
> 状态：需求初稿，待确认首发平台与发布模式  
> 关联调研：[视频解析工具调研报告](./01-research.md)

## 1. 产品概述

### 1.1 产品定位

一款本地运行的桌面视频解析与下载工具。用户粘贴公开网页或自己有权访问的媒体页面 URL，应用解析媒体信息，提供易懂的质量/格式方案，并完成下载、音视频合并、字幕处理、转换和文件校验。

核心价值不是暴露 yt-dlp 的全部参数，而是将复杂能力整理成可靠、清晰、可恢复的桌面工作流。

### 1.2 目标用户

- 需要保存自己发布、获得授权或允许下载的视频，但不熟悉命令行的普通用户。
- 需要批量保存课程、公开视频、播客或素材的内容工作者。
- 需要字幕、音频提取、播放列表筛选和格式控制的进阶用户。
- 希望保留 yt-dlp 可诊断性，但需要图形化任务管理的技术用户。

### 1.3 产品目标

- 让用户在 3 个主要操作内完成常见下载：粘贴 URL、选择预设、开始下载。
- 对单视频、播放列表、音频提取、字幕下载形成完整闭环。
- 明确展示解析、下载、合并/转码、校验等阶段。
- 应用重启、网络中断或工具异常后，任务可识别、可重试、可恢复。
- 默认不上传 URL、Cookie、日志或下载历史。

### 1.4 非目标

- 不解密或绕过 DRM。
- 不绕过付费、会员、地域、年龄或账号访问权限。
- 不保证任意站点永久可用，不维护独立站点解析规则。
- 不提供云端解析、云端存储、P2P 分发或分享链接。
- MVP 不提供通用网页浏览器、视频编辑器、媒体库播放器或订阅自动抓取；仅提供受控的平台登录窗口。
- MVP 不允许用户输入任意 shell 命令或不受控的 yt-dlp/FFmpeg 参数。

## 2. 成功指标

### 2.1 产品指标

- 新用户首次成功下载率不低于 85%，统计仅在用户明确选择加入匿名遥测时启用；无遥测时通过内测样本评估。
- 在底层工具支持且网络正常的测试集内，单视频完整流程成功率不低于 95%。
- 90% 的常见单视频任务无需展开“高级设置”。
- 解析失败时，100% 给出错误类别、可执行建议和脱敏诊断入口。
- 应用非正常退出后，100% 的未完成任务在下次启动时被标记为“已中断”，且可重试或清理。

### 2.2 工程质量指标

- Renderer 全程无 Node integration，启用 context isolation 与 sandbox。
- 所有主进程 IPC 均通过 schema 校验，不接收可直接执行的命令字符串。
- 所有发布二进制具有来源清单和哈希；更新失败不影响现有版本。
- 下载日志与诊断包不得包含 Cookie 值、Authorization 值或已知敏感查询参数。
- Windows 目标测试集覆盖解析、独立音视频合并、字幕、音频提取、取消、恢复和中文文件名。

## 3. 版本范围

### 3.1 MVP / P0

- Windows 10/11 x64。
- 单条 URL、多行批量 URL、播放列表解析。
- 视频信息预览和播放列表条目选择。
- 常用下载预设与基础高级选项。
- 视频下载、音频提取、字幕/封面/元数据处理。
- 任务队列、并发控制、进度、取消、重试、恢复。
- 下载历史、打开文件/目录、重复任务提示。
- 抖音、哔哩哔哩、YouTube、小红书隔离登录会话、Cookie 校验与显式清除。
- yt-dlp/FFmpeg 版本显示、自检、手动更新与回滚。
- 友好错误、脱敏日志和诊断包导出。

### 3.2 P1

- macOS 与 Linux。
- 下载区间、章节拆分、代理、限速计划。
- 自定义命名模板可视化编辑。
- 任务优先级、队列拖拽排序、批量修改设置。
- 应用自动更新与工具更新提醒。
- 简体中文/英文切换。
- 受控的高级 yt-dlp 参数白名单。

### 3.3 P2

- 频道/播放列表订阅与增量下载。
- 可选的本地媒体库与重复内容管理。
- 浏览器扩展“发送到应用”。
- Cookie 文件导入和显式的本机浏览器 Cookie 读取后备方案。
- 更多设备兼容预设和硬件编码器探测。

## 4. 信息架构

主界面采用任务型结构，不做营销首页：

1. **下载**：URL 输入、解析结果、格式方案和创建任务。
2. **任务**：进行中、等待、已暂停、失败任务及批量操作。
3. **历史**：已完成记录、搜索、筛选、打开文件和再次下载。
4. **设置**：下载、网络、认证、工具链、隐私、外观和关于。

窗口顶部保留全局“粘贴链接”入口和当前活动任务摘要。任务详情采用侧栏或独立详情区，避免在卡片中堆叠全部高级信息。

## 5. 核心用户流程

### 5.1 单视频快速下载

1. 用户粘贴 URL 或点击“从剪贴板粘贴”。
2. 应用校验协议并创建解析请求。
3. 展示封面、标题、作者、时长、来源和可用方案。
4. 默认选中上次使用的预设，首次使用时选“推荐视频”。
5. 用户确认保存目录并点击下载。
6. 任务进入队列，依次展示下载、合并/转码、校验状态。
7. 完成后提供播放、打开文件、打开目录和复制路径。

### 5.2 播放列表/频道集合

1. 解析后先展示集合摘要和条目数量。
2. 用户可全选、反选、按范围选择、搜索条目或排除直播/已下载条目。
3. 用户选择统一预设，也可在 P1 对单项覆盖。
4. 每个媒体条目成为独立子任务，集合展示聚合进度。
5. 单项失败不阻断其他条目，除非用户开启“遇错停止”。

### 5.3 需要登录态的内容

1. 解析返回认证相关错误。
2. 应用定位到“设置 > 登录状态”，用户选择对应平台打开隔离登录窗口。
3. 关闭登录窗口后进行 Cookie 完整性与期限校验；真实解析成功后标记为“有效”。
4. Cookie 只传给域名匹配的平台任务；运行时临时导出，进程结束后立即删除。
5. 重新解析。失败时显示底层建议，但不承诺绕过风控。

### 5.4 中断恢复

1. 暂停时停止当前受控进程树，保留 `.part`、分片或临时文件。
2. 继续时以同一输出路径重新启动任务，由 yt-dlp 尝试续传。
3. 若来源不支持续传，提示将从头开始，并在用户确认后处理冲突文件。
4. 应用崩溃或重启后，运行中任务转为“已中断”，不自动发起网络请求。

## 6. 功能需求

### 6.1 URL 输入与解析

#### FR-001 URL 输入

优先级：P0

- 支持粘贴单条 URL、多行 URL 和拖入 `.txt` URL 清单。
- 只接受 `http:` 和 `https:`；拒绝 `file:`、`javascript:`、自定义协议和控制字符。
- 自动去除首尾空白并去重，保留用户输入顺序。
- 对含敏感查询参数的 URL，界面可正常使用，但日志必须脱敏。
- 剪贴板检测必须是用户主动触发或可关闭，不在后台持续读取。

验收标准：

- 多行输入中合法 URL 被逐条识别，非法项单独标记，不影响其他项。
- URL 中包含 `&`、引号、中文或以 `-` 开头的媒体 ID 时，不会被解释为命令参数。

#### FR-002 解析状态

优先级：P0

- 状态包括：等待解析、解析中、等待选择、解析失败、已过期。
- 解析开始后 200ms 内显示可感知的进行中状态。
- 支持取消解析。
- 同一标准化 URL 和同一认证上下文的短期结果可缓存，但必须提供重新解析。

#### FR-003 媒体预览

优先级：P0

- 展示标题、封面、时长、上传者/作者、来源站点、发布日期（若有）、直播状态。
- 播放列表展示集合标题、条目数和条目选择器。
- 字段缺失时隐藏对应区域，不显示 `NA`、`null` 或技术占位值。
- 封面由主进程受控下载到本地缓存，限制协议、响应类型和文件大小；Renderer 不直接加载任意远程 URL。
- 封面加载失败时使用本地图形占位，不影响格式解析与下载。

#### FR-005 直播与首映

优先级：P0（识别）/ P1（下载）

- P0 识别预告、直播中、直播已结束和普通点播状态。
- P0 对直播回放按普通点播处理；对尚未开始或正在直播的内容明确显示“首版暂不支持实时下载”。
- P1 再评估从开头下载、从当前时刻下载、等待开播、无限时长、磁盘预估和主动结束等直播语义。

#### FR-004 可用方案生成

优先级：P0

- 将底层 formats 归并为面向用户的方案，而不是平铺全部 format ID。
- 每个方案展示：预计分辨率、帧率、视频编码、音频编码、容器、HDR（若可知）、估算大小和处理方式。
- 明确标记“直接下载”“下载后合并”“需要转码”。
- 信息不足时使用“未知”，不得虚构文件大小或兼容性。
- 提供“查看原始格式”高级入口用于诊断。

### 6.2 下载预设与选项

#### FR-010 内置预设

优先级：P0

至少提供：

- 推荐视频：在质量、兼容性和处理成本之间取平衡。
- 原始最佳质量：优先最高质量，允许 MKV/WebM 等容器。
- MP4 兼容：目标为常见设备可播放的 MP4；需要转码时明确提示。
- 仅音频（原始）：保留最佳可用音频编码。
- MP3 音频：允许选择 128/192/256/320 kbps。
- 仅字幕：不下载视频，导出所选字幕。

预设实际映射必须集中管理并带版本号，不能散落在 UI 组件中。

#### FR-011 视频选项

优先级：P0

- 分辨率上限：原始最佳、2160p、1440p、1080p、720p、480p、360p。
- 容器偏好：自动、MP4、MKV、WebM。
- 帧率偏好：自动、最高、最高 30fps、最高 60fps。
- HDR：自动、优先 SDR、允许 HDR。
- 不可满足组合时给出替代方案，不静默输出与选择不符的结果。

#### FR-012 音频选项

优先级：P0

- 格式：原始、M4A、Opus、MP3、FLAC、WAV。
- 对有多音轨信息的来源展示语言/名称选择。
- 明确区分“提取原始音频”和“转码音频”。
- 码率选项只在对应有损转码格式下显示。
- 源音频为有损格式时，选择 FLAC/WAV 要提示文件会变大且不会恢复已经损失的音质。

#### FR-013 字幕

优先级：P0

- 展示人工字幕与自动字幕，并明确区分。
- 支持多语言选择、仅下载、嵌入视频、同时保留外部文件。
- 支持输出原始格式或转换为 SRT/VTT；转换失败不应删除已下载视频。
- 容器不支持所选字幕时给出切换容器、外挂字幕或转码方案。

#### FR-014 封面与元数据

优先级：P0

- 可选下载封面、嵌入封面、写入媒体元数据、写入 info JSON。
- 默认不保存可能包含大量个人信息的页面描述全文，除非用户开启。
- 写入失败时任务可标记“主体完成、附加处理失败”，而不是整体伪装成未下载。

#### FR-015 保存位置与命名

优先级：P0

- 默认目录可配置；每次任务可覆盖。
- 默认文件名为“标题 + 媒体 ID”，降低重名概率。
- 自动处理 Windows 保留名、非法字符、末尾空格/句点和路径长度。
- 文件冲突策略：询问、跳过、覆盖、自动编号；默认自动编号。
- 播放列表默认创建集合子目录，并以序号保持顺序。
- 最终路径以 yt-dlp `after_move` 结果为准，不从预期模板猜测。

### 6.3 任务系统

#### FR-020 任务状态机

优先级：P0

单项任务状态：

`等待 -> 解析/准备 -> 排队 -> 下载 -> 后处理 -> 校验 -> 已完成`

任一活动状态可以进入：`暂停中 -> 已暂停`、`取消中 -> 已取消`、`失败`、`已中断`。

要求：

- 状态转换必须由主进程任务服务控制，Renderer 不能自行宣告完成。
- 下载完成但字幕/封面等附加步骤失败时，状态为“部分完成”。
- 每次状态变化持久化，应用崩溃后可重建。

#### FR-021 进度展示

优先级：P0

- 展示当前阶段、百分比、已下载/总大小、速度、ETA。
- 播放列表展示总条目进度和当前活动项。
- 总大小未知时显示已下载量和速度，不显示虚假百分比。
- 后处理不沿用下载的 100% 进度条，改用明确的阶段状态。
- 限制 UI 更新频率，避免高频 stdout 造成 Renderer 卡顿。

#### FR-022 队列与并发

优先级：P0

- 默认同时运行 2 个媒体任务，可配置 1-5。
- 分片并发与任务并发分开设置，避免乘法放大请求数。
- 新建任务进入队列；支持全部开始、全部暂停、重试失败项和清理已完成。
- 退出应用时询问继续后台运行或暂停并退出；MVP 若不提供托盘后台，则只提供暂停并退出。

#### FR-023 暂停、取消与清理

优先级：P0

- “暂停”保留可续传文件；“取消”默认也不立即删除，另提供“取消并删除临时文件”。
- 必须终止 yt-dlp 及其启动的 FFmpeg 子进程，不能遗留后台进程。
- 删除前展示将删除的任务临时目录，不触碰目标目录中的既有文件。
- 无法安全识别归属的文件不得自动删除。

#### FR-024 重试与恢复

优先级：P0

- 支持自动网络重试与用户手动重试。
- 认证失败、不可用格式、磁盘满、权限不足等非瞬时错误不得无限重试。
- 重试保留原任务设置和日志，同时创建新的运行 attempt 记录。
- 工具升级后重试时记录新旧工具版本。

### 6.4 历史与文件操作

#### FR-030 历史记录

优先级：P0

- 记录标题、来源、URL 指纹/脱敏形式、完成时间、输出路径、输出媒体信息、工具版本和结果。
- 支持按标题搜索，按状态、日期、来源、视频/音频筛选。
- 文件被外部移动或删除时标记“文件不存在”，不自动从历史移除。
- 支持清除单项或全部历史；清历史默认不删除媒体文件。
- 可安全规范化的页面 URL 可供“再次下载”；带签名、token 等敏感参数的 URL 不写入历史，再次下载时要求用户重新粘贴。

#### FR-031 文件操作

优先级：P0

- 使用系统默认应用打开文件、打开所在目录、复制路径、再次下载；MVP 不内置播放器。
- 传给系统 shell 的路径必须来自已完成任务记录，并经过存在性检查。
- 不允许把远程 URL 直接交给高权限 shell 执行。

#### FR-032 下载归档

优先级：P0

- 维护本地下载归档，识别相同 extractor + media ID 的重复内容。
- 重复时提供打开已有文件、仍然下载或跳过。
- 用户可关闭去重；不同格式/语言的任务允许作为不同输出保存。

### 6.5 认证、网络与隐私

#### FR-040 平台登录与 Cookie

优先级：P0

- 抖音、哔哩哔哩、YouTube、小红书分别使用独立 Electron session，禁止跨平台共享 Cookie。
- 登录窗口不启用 Node 或 preload，拒绝权限、文件下载和非白名单顶级导航。
- 校验状态区分未登录、本地完整性通过、真实解析验证有效和已失效。
- yt-dlp 只接收匹配平台的 Netscape 临时 Cookie 文件以及同会话 User-Agent；任务结束立即删除。
- 支持用户主动清除单个平台的 Cookie、缓存与站点存储。
- 首次使用前提示：Cookie 可能授予账号访问权，自动化可能触发站点限制。
- 状态数据只保存校验时间和结果，不保存 Cookie 值或账号密码。
- P2 支持选择 Netscape Cookie 文件或显式读取本机浏览器，作为内嵌登录被平台限制时的后备方案。

#### FR-041 网络设置

优先级：P0（基础）/ P1（代理）

- P0：超时、任务并发、分片并发、下载限速。
- P1：HTTP/HTTPS/SOCKS 代理，并支持按任务关闭。
- 代理密码按秘密处理，不进入普通设置 JSON 或日志。
- 默认启用合理退避，不以高并发作为“加速”卖点。

#### FR-042 隐私控制

优先级：P0

- 默认无账号、无云端、无遥测。
- 若未来加入遥测，必须明确选择加入，并说明字段、用途和保留期。
- 日志对 Cookie、Authorization、token、签名参数及本地用户名路径做脱敏。
- 诊断包导出前显示内容清单，允许用户预览。
- 活动任务若必须保留带敏感参数的 URL 以支持重启恢复，应使用 OS 安全存储加密；任务结束后只保留 URL 指纹和脱敏形式。

### 6.6 工具链管理

#### FR-050 工具自检

优先级：P0

- 显示 yt-dlp、FFmpeg、ffprobe 版本、路径、来源和完整性状态。
- 首次启动和更新后执行：版本检查、解析测试、FFmpeg 合并测试、ffprobe JSON 测试。
- 自检失败时禁止开始会受影响的任务，并提供修复动作。
- 允许高级用户选择外部二进制，但必须明确“非内置、未验证”。

#### FR-051 yt-dlp 更新与回滚

优先级：P0

- 支持 stable/nightly 通道，默认手动检查。
- 只允许配置好的官方源；MVP 不允许任意仓库更新。
- 下载后校验官方 checksum/signature，再进行冒烟测试和切换。
- 保留上一可用版本，失败自动回滚。
- 更新时如果有运行任务，等待任务结束或要求用户先暂停。

#### FR-052 FFmpeg 更新

优先级：P1

- MVP 随应用发布固定版本，仅展示版本和来源。
- 独立更新上线前必须解决构建来源、许可证、签名和跨平台产物映射。
- 第三方 notices 自动由发布清单生成，不能手工漏项。

### 6.7 错误与诊断

#### FR-060 错误分类

优先级：P0

至少区分：

- URL 无效或没有媒体；
- 当前 extractor 不支持/已失效；
- 需要登录或 Cookie 已失效；
- 内容不可用、私有、地区限制或权限不足；
- 请求过多/限流/风控；
- 无匹配格式；
- 网络超时、DNS、TLS 或代理错误；
- 磁盘空间不足、目录不可写、文件占用；
- FFmpeg 缺失、合并失败或转码失败；
- 工具崩溃、输出协议无法解析或未知错误。

每类错误包含：短标题、用户可理解的说明、1-3 个建议动作、错误代码和“查看技术详情”。

#### FR-061 日志

优先级：P0

- 每个 attempt 有独立结构化日志，包含时间、阶段、工具版本和退出码。
- 普通模式不启用可能输出页面、请求头或 Cookie 的超详细 yt-dlp 调试参数。
- 技术详情展示脱敏后的 stderr；原始日志若包含秘密不得落盘。
- 支持复制错误摘要和导出诊断包。

## 7. 交互与文案原则

- 使用“解析链接”描述信息获取，使用“下载”描述实际网络传输。
- 不使用“破解、万能、100% 支持、无限制”等表述。
- 对普通用户展示“推荐、原始最佳、兼容 MP4、仅音频”，format ID 放在高级详情。
- 文件大小为估算时必须标注“约”；未知时不显示 0 B。
- “暂停”旁说明能否续传由来源决定；“取消”与“删除文件”分开。
- 错误动作使用明确命令，如“重新解析”“选择 Cookie”“切换到 nightly”“更换保存目录”。
- 用户首次启用 Cookie、覆盖文件或删除临时文件时需要确认。

## 8. 非功能需求

### 8.1 性能

- 应用冷启动至可输入状态：目标 Windows 测试机 P95 小于 3 秒。
- 解析/任务输出高频更新时，界面交互保持流畅，不阻塞输入与窗口拖动。
- 任务进度 UI 刷新不高于每任务每秒 4 次，底层日志仍完整记录。
- 1000 条历史记录下，搜索与筛选结果在 200ms 内出现。

网络解析耗时受站点和网络影响，不设绝对完成时限，但 200ms 内必须显示状态，且超时可配置。

### 8.2 可靠性

- 任务状态采用原子持久化；写入中断不能破坏整个历史。
- 应用启动时识别未正常结束的 attempt，并标记已中断。
- 工具更新使用原子切换，当前版本始终可回滚。
- 目标磁盘空间不足时尽量在下载前预警；无法估算时在运行中持续监控写入错误。
- 同一路径并发写入必须串行化或改名，禁止两个任务覆盖同一文件。

### 8.3 安全

- Renderer：`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`。
- 使用本地自定义协议和严格 CSP，不使用 `file://` 加载应用页面。
- IPC 以具体动词建模并做 schema 校验，不暴露通用 `exec`、任意读写文件或任意打开 URL 接口。
- 所有外部进程使用绝对路径、参数数组、`shell: false` 和受控环境变量。
- 禁止从下载目录加载可执行代码、插件或 Renderer 资源。
- 外部链接仅允许 `https:` 且在调用系统浏览器前做 allowlist/确认。
- 发布启用适用的 Electron fuses、ASAR 完整性和代码签名。

### 8.4 可访问性

- 所有功能可用键盘完成，焦点顺序与可见焦点明确。
- 图标按钮具有可访问名称和 tooltip。
- 状态不只用颜色表达；进度和错误可被屏幕阅读器读取。
- 文本与背景达到 WCAG AA 对比度目标。
- 尊重系统减少动态效果设置。

### 8.5 国际化

- MVP 界面语言为简体中文，代码中不得硬编码用户文案。
- 错误映射基于稳定错误码，不依赖中文/英文 stderr 文本作为唯一判断。
- 路径、标题、字幕语言和元数据全程使用 Unicode。

## 10. 技术边界建议

这不是完整技术设计，但以下边界直接影响需求可实现性：

- Electron Main：窗口生命周期、受控 IPC、文件选择、系统操作和任务服务。
- Preload：仅暴露类型化的解析、任务、设置、工具和文件操作接口。
- Renderer：显示状态与提交意图，不持有外部进程句柄，不直接读 Cookie。
- Task Service：队列、状态机、持久化、进程树、输出解析和重试策略。
- yt-dlp Adapter：命令参数构建、JSON 解析、结构化进度、错误归类、版本能力适配。
- FFmpeg Adapter：路径管理、探测、转码/校验命令和错误归类。
- Tool Manager：manifest、下载、校验、冒烟测试、激活和回滚。

CLI 调用约束：

- 一律使用应用自带配置并加 `--ignore-config`。
- 解析使用 JSON，不把 stdout 的自然语言作为数据协议。
- 进度使用带应用专属前缀的 `--progress-template`，未知行只进入脱敏日志。
- 完成路径使用 `after_move:filepath`。
- URL 始终作为独立参数传递，禁止 shell 拼接。
- 每个任务有独立临时目录，清理只能作用于该目录的已登记文件。

## 11. MVP 验收场景

1. 粘贴一个公开单视频 URL，可以看到标题、封面、时长和至少一个可用方案。
2. 选择“推荐视频”，任务完成后输出文件存在，ffprobe 可读取，历史记录路径正确。
3. 对独立音视频流，界面从“下载”进入“合并”，最终只保留正确的目标文件和按策略保留的临时文件。
4. 选择 MP3 192 kbps，可以看到转码阶段并得到可探测的音频文件。
5. 选择人工字幕和自动字幕时界面有明确区分，选中的外部字幕能随视频保存。
6. 播放列表可选择部分条目，失败的一个条目不影响其余条目完成。
7. 下载中暂停并继续，不产生第二个错误命名的目标文件；不支持续传时给出提示。
8. 强制结束应用后重启，原运行任务显示“已中断”并可重试。
9. 磁盘目录不可写时，在下载前或首次写入时给出“目录不可写”，不归类为网络错误。
10. Cookie 文件仅在用户选择后使用，导出的诊断日志中不包含 Cookie 值。
11. yt-dlp 更新校验失败时拒绝激活；新版本冒烟测试失败时继续使用旧版本。
12. 输入包含引号、`&`、空格、中文和以 `-` 开头 ID 的 URL，不发生命令注入或参数错位。
13. 点击取消后，yt-dlp 和 FFmpeg 进程均结束；用户未选择删除时临时文件保留。
14. 完成路径与后处理实际扩展名一致，不依赖解析阶段猜测。
15. 无网络、超时、认证失败、无格式、磁盘满和 FFmpeg 失败分别显示不同错误与建议。

## 12. 待产品确认的决策

以下选择不阻塞原型，但会影响首个可发布版本：

1. **首发平台**：建议 Windows 10/11 x64；是否首版必须同时支持 macOS/Linux。
2. **发布模式**：开源免费、闭源免费或商业产品。该选择会影响许可证审查、更新服务和品牌设计。
3. **产品边界**：是否只做“用户主动下载”，还是后续需要频道订阅和自动增量下载。
4. **认证范围**：MVP 是否接受浏览器 Cookie 读取，还是仅允许用户选择 Cookie 文件。
5. **默认工具通道**：建议安装包固定已验证版本，用户可手动切换 stable/nightly；是否允许自动更新。
6. **高级能力**：是否需要面向技术用户开放受控参数；不建议开放原始 shell 输入。
